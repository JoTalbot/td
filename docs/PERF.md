# Производительность

Замеры — скрипт `~/.smoke_tests/perf_benchmark.gd` (в репо не хранится):
`~/bin/godot --headless --path . --script ~/.smoke_tests/perf_benchmark.gd`

Сцена-стресс: все 8 слотов заняты орудиями, волна 20+, time_scale ×6,
паузы между волнами принудительно убраны — поле боя постоянно плотное.
Headless с нулевым рендерером меряет CPU-логику (геймплей, твины,
хозяйство партиклов/групп), не GPU.

## Снапшот (коммит с влитыми оптимизациями)

| Метрика | Значение |
|---|---|
| Кадры замера | 900 |
| avg | 7.0 мс |
| p50 | 6.9 мс |
| p95 | 10.4 мс |
| max | 47.5 мс (разовый скачок спавна) |
| max врагов одновременно | 26 |
| max снарядов | 6 |
| max взрывных FX | 8 (бюджет) |

Регрессионные ворота в бенче: avg ≤ 8 мс, p95 ≤ 16 мс, fx ≤ 8, врагов ≥ 6.

## Применённые приёмы

- **Бюджет вспышек взрывов** (`Junk.explosion`): узлы в группе `fx_explosion`;
  при ≥8 живых эффектах новый взрыв не строится, при ≥4 — без OmniLight.
  `Junk.perf_explosion_lights = false` отключает свет вспышек вовсе.
- **Лампы вспышек орудий** (`Weapon._flash`): `visible=false` в простое —
  потухшая лампа покидает световой кластер мобильного рендерера; до фикса
  8 вечных OmniLight висели в кластере постоянно.
- Снаряды в группе `projectiles` (удобно для бюджетов и замеров).
- Партиклы пыли умеренные (30 на врага), тени только от солнца,
  рендерер `mobile` — см. AGENTS.md.

## Что НЕ делаем

- Не пулим снаряды/врагов вручную — пока логика вписывается в 60 FPS с запасом;
- не режем визуал (изменение стиля — только через пользователя).
